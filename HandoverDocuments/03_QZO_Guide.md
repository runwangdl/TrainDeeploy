# 03 — Quantized Zeroth-Order (QZO) on-device fine-tuning of SpeechNet

**Scope.** This guide documents the quantized zeroth-order (QZO) on-device fine-tuning pipeline for
SpeechNet: an int8 convolution datapath whose int8 weights and int32 requant biases are perturbed
and updated on the device by the MeZO algorithm, with fp32 BatchNorm affine parameters and an fp32
classifier trained alongside. The pipeline spans `Onnx4Deeploy` (Brevitas model, calibration,
integerization, two-graph ZO export, device-faithful host reference) and `TrainDeeploy` (vendored
Deeploy: parsers, templates, tile constraints, C kernels, MeZO harness, runners). Multi-round and
multi-subject host PyTorch simulations were run with the host-simulation code in
SilentWear/SilentWear/PyTorch_for_On_Device/CleanUp/ (not part of these repositories). It runs on
Siracusa (GVSoC) and GAP9 (GVSoC, cluster only; NE16 is in `04_FusedQZO_NE16_Guide.md`, not here).

## 1. Concept

### 1.1 MeZO in one block

```
z ~ Rademacher(±1)^d                      one direction per update step, regenerated from a seed
L+ = L(θ + εz; x),  L− = L(θ − εz; x)     two forward passes, same z ("antithetic pair")
g_proj = (L+ − L−) / (2ε)                  projected gradient (scalar)
θ ← θ − lr · g_proj · z                    the update, along z only
```

With `n_accum` mini-batches per step the device sums `(L+ − L−)` over the batches and divides by
`2ε·n_accum` (a MEAN: `denom = 2.0f * ZO_EPS * n_accum`,
`DeeployTest/Platforms/Siracusa/src/deeploymezotest.c:154`). The BP harness instead SUMS its
accumulated gradients with no 1/N; copying one convention into the other (e.g. in a host
simulation) silently rescales the effective step by `n_accum`. No backward graph and no stored
activations are needed; only the seed must be remembered to regenerate `z` for the update.

### 1.2 What quantization changes

SpeechNet has 22 trainable tensors in this design:

| group | count | representation | grid quantum |
|---|---|---|---|
| conv weights | 5 | int8, per-output-channel scale `s_w[c] = max|W[c]|/127` (data-free) | `s_w ≈ 0.0013–0.0034` (block medians, exp_calibration) |
| conv biases | 5 | int32 in the RequantShift `add` domain (`round(b·2^16/s_out)`), i.e. the accumulator scale `s_in·s_w[c]` | about `s_w/5` (finer, because `s_in ≈ 0.2`) |
| BN γ, β | 10 | fp32 | none |
| fc weight, bias | 2 | fp32 (classifier kept float) | none |

Two consequences define QZO:

1. **The perturbation is an integer.** A float `±ε` becomes a per-channel integer step
   `noise_q = round(ε / s_w[c])`. It is encoded at export as a fixed-point vector
   `pmul[c] = round(ε/s_w[c] · 2^S)` (`S = 15` for int8 weights, `16` for int32 biases) and applied
   by an integer kernel as `noise_q = (±pmul[c] + 2^(S−1)) >> S`. For ε = 0.01 this is 3–8 LSB for
   the convs, so the probes are exact and informative.
2. **The update is also rounded to the grid.** The device scales the same `pmul[c]` by
   `coeff/ε` where `coeff = −lr·g_proj`, so the update is `round(coeff/s_w[c])` LSB. At the float-ZO
   lr 3e-6 this is ≈ 0.03 LSB and rounds to 0 on every step: the **LSB stall** (§1.3). The int32
   biases live on a ~5× finer grid and do move (±1..±7 LSB in exp8).

All quantization scales are frozen at export: per-tensor activation scales from calibration (§3),
per-channel weight scales, and the fused RequantShift constants. Nothing is recalibrated at runtime.

### 1.3 The LSB stall and its three answers

Stall criterion per channel: a weight moves only when `|coeff|/s_w[c] ≥ 0.5`, i.e.
`|g_proj| ≥ 0.5·s_w[c]/lr`. The rounding is memoryless, so sub-LSB updates are discarded, not
accumulated. The probe is ~100× larger than the update because ε must be large (finite-difference
measurability) while lr must be small (ZO stability):

```
update in LSBs = round(coeff / s_w) = round(lr·|g| / s_w) ≈ round(0.03) = 0     (lr 3e-6, mean |g| ≈ 14.5)
probe  in LSBs = round(  ε   / s_w) = round(0.01 / 0.0015) ≈ 3–8                ← survives
```

Measured facts (host Brevitas study, `Onnx4Deeploy/QZO_exp/exp_calibration/results.json`, keys
`probe`, `regimes`, `old_scales`): mean |g| 14.48 vs 14.55 under the old vs the corrected
calibration (shared z), max ≈ 53–82; at lr 3e-6 zero of 14,880 conv weights move, under both
calibrations. Calibration changes the *forward* (11 % → 85.6 % zero-shot across procedures, §3) but
cannot touch the stall: `s_w` is data-free and `g` is calibration-invariant. A controlled Brevitas
experiment whose regimes differ only in the update rule (same frozen scales, data, seed) confirms the
cause: master weights move every step, direct int8 moves on 2 of 100 steps, only on gradient-noise
spikes (`TrainDeeploy/DeeployTest/experiments/deliverable/exp8_QZO_8steps_4accum/brevitas_stall_study/results.json`).

| answer | mechanism | status | evidence |
|---|---|---|---|
| **lr 1e-5** (deployed) | places `0.5·s_w/lr` at the tail of the |g| distribution, so only the ~1 % strongest steps move whole channels ±1 LSB (34 of 2700 steps moved anything; the minimum |g| on a moving step was 49.4 = the predicted `0.5·s_w_min/lr`; union 77 % of conv weights over the round). Weak steps are still discarded: training happens through rare, large, whole-channel jumps. Fine-grid tensors train fully; the coarse-grid block-0 weights barely move | on device (exp12, exp19) | `exp_calibration/results.json` keys `regimes` (entry pooled@99.99, direct, lr1e-05, round1) and `anatomy`; scripts `run_lr_sweep.py`, `run_move_anatomy.py`; cross-fold caveat in §7 item 20 |
| **master weights** | fp32 shadow copy `W_master += coeff·z` (unrounded, accumulates), `w_int8 = round(W_master/s_w)` every forward (~60 kB L2; on device: persistent master buffers plus a `Quant` op in the update graph) | host only | `exp_calibration/results.json` key `regimes`, entry pooled@99.99, master, round1 (87.22 % round 1, 76 % of conv weights moved) |
| **ECO error feedback** | inject the rounding residual into an SGD-momentum buffer (below); moves weights at lr 3e-6 without a master copy | host only | `Onnx4Deeploy/QZO_exp/exp15_QZO_eco/results.json`, `run_eco.py` |

**ECO (error-compensating optimizer, arXiv:2601.22101) as transferred to QZO.** Per conv weight,
with per-channel scale `s_w`, `g = coeff·z` (`coeff = (L+−L−)/(2ε·n_accum)`, `z = ±1`), pinned lr and β:

```
m_tilde  = β·m + (1−β)·g
th_tilde = w_int·s_w − lr·m_tilde
w_new    = clamp(round(th_tilde/s_w), −127, 127)      # RTN; the SR variant reuses the xorshift32 PRNG
e        = th_tilde − w_new·s_w                        # rounding residual (computed against the clamped value)
m        = m_tilde + α·e,  α = (1/lr)(1 − 1/β)         # "memory-free": assumes e_t ≈ e_{t+1}
         # exact EF instead stores e:  m = m_tilde + (1/lr)·e_prev − (1/(lr·β))·e
w_int    = w_new
```

What the host study established (`exp15_QZO_eco/results.json`, 4 incremental rounds, lr 3e-6):
the residual injection, not the momentum, breaks the stall (SGD momentum with the injection removed
moves 0 % of weights, exactly like plain direct int8); α is never tuned, β is the knob (β 0.99 makes
α ~15× smaller, the injection never crosses an LSB within a round, and the conv stalls again);
β 0.9 works. The memory-free assumption holds in ZO: consecutive RTN residuals have cosine 0.998,
because the residual is dominated by the slowly varying momentum, not the fresh rank-1 `coeff·z`.
Memory-free RTN is write-sparse (11.8 % of conv weights ever written, on 17 % of steps); SR and exact
EF write ~100 % every step. Memory: memory-free ECO needs an fp32 `m` (~60 kB L2), the same as master
weights, because this ZO base has no momentum buffer to reuse; exact EF needs `m` + `e` (~120 kB);
a classical int16 EF residual alone would be ~30 kB. α ≈ −3.7e4 at (lr 3e-6, β 0.9), so `m` and
`α·e` must stay fp32; exact EF avoids the 1/lr blow-up. Because the fp32 BN γ/β keep training by
float ZO, the conv-frozen floor is already 85.42 %, so all conv-training methods live in a ~1.4 pp
band in this protocol; the movement and the ablation, not the accuracy delta, are the robust signal.

Refuted alternatives (same harness): ceiling update (51.67 %,
`Onnx4Deeploy/QZO_exp/exp4_ceiling/results.json`); stochastic rounding alone (85.00 %, ≈ zero-shot,
`exp4_ceiling/sr_control/results.json`), because its per-step ±1 LSB variance hurts; a percentile
weight scale (s_w from p95/p99 instead of abs-max) shrinks the grid only ~0.6× (stall threshold
164 → 97, still above max|g| ≈ 82 at 3e-6) while clipping 6–9 % of the largest weights, and at lr 1e-5
abs-max wins (90.0 % vs ≤ 88.9 %; `exp_calibration/results.json` key `weight_percentile`) — the
weights are near-Gaussian per channel (worst-channel max/p99 = 1.80, 0 of 104 channels above 2×), so
`max|W|/127` is already near-optimal; ε tuning, because `g = (L+−L−)/2ε` cancels ε to first order
(measured flat over ε ∈ [0.002, 0.1], key `eps_probe`; small ε kills the probe, large ε adds curvature
bias, ε = 0.01 is well placed). Raising `n_accum` is not a substitute either: it averages within a
step and does not change the step magnitude.

## 2. The graph that Onnx4Deeploy emits

### 2.1 Datapath per block

```
input fp32 ─Quant(s_act)→ int8 ─┬──────────────────────────────────────┐
w_int8   (graph INPUT) ─RQSPerturbRademacher→ ŵ ─┤ Conv (2-input, int8) → int32 │→ RequantShift(mul[c], add=b̂) → int8
b_rqsadd (graph INPUT) ─RQSPerturbRademacher→ b̂ ─┴──────────────── as the requant `add` ─┘
  → Dequant(s_out) → fp32 BatchNormInternal(γ̂, β̂; frozen running stats) → ReLU → MaxPool → Quant(s_in_next) → …
… ×5 blocks → GlobalAveragePool → Reshape → float Gemm(ŵ_fc, b̂_fc) → SoftmaxCrossEntropyLoss(logits, label) → loss
```

Node census of the current training graph `TrainDeeploy/SpeechNet_Test/exports/qzo_single_step/network_zo_train.onnx`
(byte-identical to the exp19 training graph and to `speechnet_qzo19_train/network.onnx`; verified by loading it): 24 graph inputs (`input`, `label`, 10 BN γ/β, 5 `blocks.N.conv.weight_int8`,
5 `blocks.N.conv.bias_rqsadd`, `fc.weight_fp32`, `fc.bias_fp32`); 10 `RQSPerturbRademacher`
(domain `mezo`), 12 `PerturbRademacher` (float), 5 `Quant`, 5 `Conv`, 5 `RequantShift`, 5 `Dequant`,
5 `BatchNormInternal` (domain `com.microsoft`, `training_mode=1`, 5 outputs), 5 `Relu`, 3 `MaxPool`,
1 `GlobalAveragePool`, 1 `Reshape`, 1 `Gemm`, 1 `SoftmaxCrossEntropyLoss`. Leading `Quant` attributes:
`scale = 22.296875` (= 2854/128), `zero_point = 0`, `bit_width = 8`, `signed = 1`.
The update graph `network_zo_update.onnx` has 22 inputs, 22 outputs named `<param>_updated`, and
only the 22 perturbation nodes (same `idx`, `seed`, `*_pmul` as the training graph).

Design decisions and why (each has a hardware reason):

- **Offline int8 weights as graph inputs, not initializers.** They must be mutable, persistent and
  shared by name between the two graphs; `Deeploy` aliases them through
  `DeeployTest/testUtils/codeGenerateTraining.py:_patch_shared_buffers` (pointer redirection). The
  shipped upstream QMCUNetZO fixture works differently: its weights are initializers, which Deeploy
  emits as writable (not `const`) `static PI_L2` arrays; the update op has input name = output name =
  weight name, so it writes in place, and the train and update networks share the weight through an
  identical global C symbol (`extern` in the update translation unit). That fixture also has no
  `−lr·g_proj` update at all (its update graph re-applies the fixed ε perturbation; no lr, no
  `ZORuntime`), which is why it never met the LSB stall; with a real gradient-scaled update and its
  direct-int8 kernel it would stall exactly as ours does at lr 3e-6.
- **2-input Conv with the bias folded into the RequantShift `add`.** The PULP int8 kernel has no bias
  argument; `Deeploy/Targets/PULPOpen/TopologyOptimizationPasses/Passes.py:_merge_conv_rq_fun` builds
  `RequantizedConv` as `list(conv.inputs) + list(rqs.inputs[1:])` = `(data, weight, mul, add)`.
  A 3-input conv would yield an unmappable 5-input node. The bias therefore lives in `add` as a
  per-channel int32 variable, which keeps it perturbable.
- **Per-channel RequantShift.** `mul[c] = round(s_w[c] · s_in/s_out · 2^16)`, `div = 2^16`.
- **`+div/2` baked into the bias initializer** (`add = round(s_w·b·s_in/s_out·2^16) + 32768`),
  because the merge pass only bakes rounding into a constant add; see §7 for the ZO consequence.
- **Float classifier.** PULP has no bare int8 GEMM, and int8 logits (256 levels over 9 classes)
  would destroy the small `L+ − L−` signal. The fc weight/bias are dequantized back to fp32
  (`w_fp32 = w_int8·s_w`), the fc input activation quant is bypassed, and fc is float-perturbed.
- **BN unfolded, fp32, frozen running stats** (`BatchNormInternal`, gated on device by
  `-D BN_FROZEN_STATS=ON`). Folding BN into the conv was tested on host and loses the gain: folded best 87.2 % vs unfolded
  88.3–89.4 % in the same Brevitas harness (`Onnx4Deeploy/QZO_exp/exp14_fold_BN/results*.json`,
  `fold_bn_sim.py`). Why: folding moves the per-channel BN scale into the conv, so block 0's folded
  weights become tiny (s_w 1.7e-5–9e-5) and ε = 0.01 is 112–591 LSB, saturating every perturbed
  forward; activation calibration must be redone without clipping (pooled@100); and the smooth
  trainable capacity of the unfolded design (one fp32 gain + bias per channel in every block) is lost.
  Folded BN with a direct-int8 update never beats zero-shot; only an LSB-domain master-weight variant
  reaches 87.2 %.

### 2.4 The host reference (why bit-exact is attainable)

The reference is not PyTorch. `run_onnx_graph` executes the identical ONNX graph with device
semantics, and the multi-step loop in `_export_qzo_training` mirrors the harness op for op:

```python
_denom = f32(f32(f32(2.0) * f32(eps)) * f32(n_accum)); g_proj = f32(acc / _denom)
coeff  = f32(f32(-lr) * g_proj); ratio = f32(coeff) / f32(eps)        # device: override / eps_baked
mul_flat = np.rint(mul_flat.astype(np.float32) * np.float32(eps_ratio))  # mirrors lrintf(m * eps_scale)
```

Op mirrors (`onnx_node_implementations.py`, originals kept as `# [exp11-orig]`): `Quant` (fp32
multiply by the fp32 reciprocal, zero-point before rounding, `±0.5` then truncate — line 880),
`Dequant` (fp32), `RequantShift` (int32 wrapping arithmetic; rounding added only when `add` is an
initializer or `QZO_FORCE_REQUANT_ROUND` is set — line 979), `BatchNormInternal` (frozen-stats,
device association order — line 578), `GlobalAveragePool` (sequential sum — line 662), `Gemm`
(6-way unroll — line 466), `SoftmaxCrossEntropyLoss` (sequential — line 846).
`_perturb_rqs_rademacher` (line 217) reproduces the C kernel: xorshift32 per 32 elements, per-core
chunking with `NUM_CORES`, seed scramble `seed*1664525+1013904223`, per-channel `M[i // elems_per_channel]`
(`np.repeat`, the B5 fix), `(r·m + 2^(S−1)) >> S`, clip to `[−127, 127]`.

## 3. Calibration

Weight scales are data-free. Activation scales need data, and this is the one input that changes
whenever the base weights change.

**Procedure (current):** `Onnx4Deeploy/QZO_exp/exp_calibration/calib_pooled.py` —
`collect_pooled(model, X, batch_size=64)` pools |x| at each of the 12 activation-quantizer sites over
all 1800 pretraining windows (fold 3: sessions 1+2, 10 h5 batches × 180), `thresholds_from_pool(..., [p])`
takes one p-th percentile of |x| per site (an absolute-value percentile), `freeze_act_thresholds` installs
`ConstThreshold` (scale = t/128, asserted). Written as `{site: threshold}` JSON and baked at export via
`QZO_POOLED_THRESHOLDS`. **The current setting is p = 99.9**
(`TrainDeeploy/SpeechNet_Test/calibration/pooled_999_fold3_ref.json`); exp19's device round used p = 99.99.

Threshold `t` → scale `s_x = t/128` (the `Int8ActPerTensorFloat` convention: `RescalingIntQuant`
divides by `int_scaling_impl(8) = 128`). Pooling all |x| and taking one percentile at the end — not
a per-batch statistic folded by EMA — makes the threshold a pure data property, independent of batch
size and ordering.

**Which percentile: 99.9 on the correct weights.** The choice was made twice. On the correct
(`artifacts_reference`) weights, a host sweep of the QZO round-1 recipe (S01, fold 3, lr 1e-5, 200 epochs,
one seed; host-simulation code in `SilentWear/SilentWear/PyTorch_for_On_Device/CleanUp/exp3_QZO_simulation`,
outside these repositories) gives:

| percentile | batch 1 (zero-shot) | batch 2 (after round 1) | mean batches 2–5 |
|---|---|---|---|
| 99.0 | 65.00 | 87.78 | 83.33 |
| **99.9** | 72.22 | **89.44** | **86.39** |
| 99.99 | 73.33 | 88.33 | 85.56 |
| 99.999 | 74.44 | 78.89 | 78.33 |
| 100 (abs-max) | 22.78 | 33.89 | 38.75 |

99.9 and 99.99 sit on a flat optimum: over four subjects (S01–S04) the mean of batches 2–5 is 75.73 at
99.9 against 75.56 at 99.99, a single-seed difference. 99.9 is the current setting because it is best for
the fine-tuned model on S01 and because every later host study on the correct weights uses it (the QZO+ECO
simulation, the half-batch study, the S02–S04 epoch sweeps), so device runs at 99.9 compare directly with
them. The device numbers of exp19 (85.00 %) are at 99.99.

**Why 99.99 was chosen first, and why pooled** (on the stale `artifacts/` weights;
`Onnx4Deeploy/QZO_exp/exp_calibration/results.json`, keys `pools`,
`sweep`, `float_ref`): the raw EMG has an artifact tail (block-0 input 99.9 % = 1,309; 99.99 % =
2,854; max = 59,656, ~45× the 99.9th percentile), so abs-max and 99.999 waste the int8 grid on
artifacts. Zero-shot batch-2 accuracy by procedure: pooled@99.99 **85.56 %**, legacy 8-window 84.44 %,
pooled@99.9 82.22 %, float 81.67 %, pooled@99.999 55.56 %, abs-max 31.11 %, uncalibrated (shipped,
scale 1/128) 11.11 % (stale `artifacts/` weights). That zero-shot ranking favoured 99.99; on the correct
weights the fine-tuned accuracy favours 99.9 (table above). Either way the tail must be clipped: the
legacy path —
what runs when `QZO_POOLED_THRESHOLDS` is unset — is a single Brevitas `calibration_mode(model)` pass
over ~8 session-3 windows with three defects: Brevitas computes its 99.999 percentile per call, which
for ≤ 630k values is the max (outlier-inflated); it folds calls with a running mean (dependent on the
batching schedule); and the windows come from the target session instead of the pretraining
distribution. It reaches 84.44 % by luck and is not reproducible methodology.

**Must be regenerated with the weights**: moving from `artifacts/` to `artifacts_reference/` changed
11 of 12 thresholds (up to +66.8 %, `blocks.2.conv.output_quant` 11.36 → 18.95; compare
`TrainDeeploy/DeeployTest/experiments/deliverable/exp12_QZO_clean_round_1/fixture/pooled_9999_fold3_fresh.json` with
`TrainDeeploy/SpeechNet_Test/calibration/pooled_9999_fold3_ref.json`); only
`blocks.0.conv.input_quant = 2854.0` stayed, because it is computed from the raw EMG. That value is
the determinism check at 99.99: `scale = 22.296875` on the leading `Quant` (logged as
`block0-in threshold=2854.0000 -> scale=22.296875` in
`TrainDeeploy/DeeployTest/experiments/deliverable/exp19_QZO_round1_correct_weights/logs/ref_calib.log`).
At 99.9 the same check is `blocks.0.conv.input_quant = 1309.0`, scale 10.2265625
(`TrainDeeploy/SpeechNet_Test/logs/calibrate_pooled.log`).

**Scripts:** `TrainDeeploy/SpeechNet_Test/scripts/calibrate_pooled.py --percentile <p ...> --out <json ...>`
computes the thresholds for any percentile from one pooled collection (it is step (a) of exp19's script with
the percentile as a parameter; it reproduces exp19's 99.99 file exactly).
`TrainDeeploy/DeeployTest/experiments/deliverable/exp19_QZO_round1_correct_weights/run_ref_and_calib.py`
is what exp19 ran (99.99 thresholds → `fixture/pooled_9999_fold3_ref.json`, plus the fc-float PyTorch
reference → `results/pytorch_ref.json`). The study code reads `QZO_ARTIFACTS_DIR` (default `artifacts_reference`;

### 4.4 Kernels (C)

`TargetLibraries/PULPOpen/src/RandomNoiseQuant.c`:

```c
void ApplyPerturbQuantRademacher_CHW(int8_t *pweights, int8_t *pweights_dest, const int32_t *M, int32_t S,
        uint32_t channel_width, uint32_t seed, uint32_t size, uint32_t start_offset, uint32_t dir, float32_t eps_scale)
  rng_state = seed*1664525u + 1013904223u; rounding = 1 << (S-1); sgn = dir ? 1 : -1;
  per 32 elements: rng_state = Xorshift32(rng_state); r = sgn * ((bits & 1) ? 1 : -1);
  m_val = M[(start_offset + i) / channel_width];                       // per-output-channel (B5 fix; was %)
  if (eps_scale != 1.0f) m_val = (int32_t)lrintf((float32_t)m_val * eps_scale);   // update coefficient
  noise_q = (r * m_val + rounding) >> S;  dest[i] = CLAMP(w[i] + noise_q, -127, 127);
```

`ApplyPerturbQuantRademacher_i32` is the int32 twin without the clamp. The same kernel serves the
±ε probes (`eps_scale = 1`) and the `−lr·g_proj` update (`eps_scale = coeff/ε`); algebraically
`noise_q = round(coeff/s_w)`. `#include <math.h>` for `lrintf` is needed on GAP9. The file carries
`#pragma clang optimize off`. The RequantizedConv kernel is pulp-nn's `pulp_nn_conv` + `pulp_nn_bn_quant_i8`
(`(acc·mul + add) >> 16`, truncating).

ZO runtime globals: `TargetLibraries/PULPOpen/inc/kernel/ZORuntime.h` / `src/ZORuntime.c`:
`perturbation_sign`, `perturb_seed_base`, `perturb_eps_override`, `perturb_eps_use_override`,
`perturb_eps_baked` (set to `ZO_EPS` by the harness so the integer kernels can form the ratio).

## 7. Known pitfalls and lessons

Each: symptom; cause; fix.

1. Device logits ~2000× off. `inputs.npz` used name keys and `testMVPTraining` maps sorted keys
   positionally. Save `arr_NNNN` in graph-input order (B1, Onnx4Deeploy `a819f19`).
2. int8 conv input saturated `[-31,-128,…]`. The device `QuantTemplate` multiplies by `scale`; our
   graphs carry the ONNX step size. `QuantParser` passes `1.0/scale` (B2, TrainDeeploy `7c22a0e`).
   A `QuantPatternPass`-fused graph that already carries the reciprocal would double-invert; emitting the
   reciprocal at export is the clean long-term fix (open).
3. Host loss 9.07 instead of ~1.3. `load_batches` shape assert tripped on a 3-D shape and the export
   silently fell back to random calibration. Pass `(1,)+ishape[1:]`; grep the export log for
   "using random calibration" (B3).
4. Frontend mapping fails at layer L2. Graph-input types inferred from npz values typed int8/int64 as
   float. `_ONNX_ELEM_TO_PTR` from the ONNX `elem_type` (B4).
5. Losses 4–10 vs host 1.3 after everything else. Kernels indexed `M[i % channel_width]` while the tile
   constraint supplies channels-first `channel_width` (bias broadcast `M[0]`, weight read out of bounds).
   `M[i / channel_width]` in `_CHW` and `_i32`, `np.tile → np.repeat` on host (B5). Channel-0-only probes
   hide every per-channel bug; probe past channel 0.
6. Zero-shot ≈ chance under pooled calibration. `build_int8_forward` used a uniform 1/128 requant ratio.
   Trace per-layer `s_in`/`s_out` from the graph (Onnx4Deeploy `bc147f6`).
7. QZO trains down (83.89 %) while Brevitas trains up. The variable requant `add` was truncated (the
   merge pass bakes `+div/2` only for a constant add); floor's −0.5 LSB is not antithetic-symmetric and
   sign-flips `g_proj`. Bake `+div/2` into `bias_rqsadd` at export (`3b710e6`); subtract it again when
   injecting dumped weights into an inference fixture; a standalone RequantShift must set `rqs_rounding`
   from whether its add is constant (second site, `RequantShiftTemplate.py`).
8. 9/9 logit errors on device inference. `BatchNormInternal` used batch stats. `-D BN_FROZEN_STATS=ON`
   on every build, including the untiled eval runner.
9. Thousands of loss errors with a correct forward. `-ffast-math` FMA/reassociation in `BatchNorm.c`/`Gemm.c`
   plus picolibc `expf/logf`, amplified by `round()`. `DEEPLOY_STRICT_FP32=ON` + `DEEPLOY_STRICT_FP32_FILES`;
   confirm the `[QW strict-fp32]` lines in the build log. Single-step is bit-exact under either build.
10. QZO step 10× slower than float ZO. Generic single-core Quant/Dequant templates and double-precision
    literals. Wire the PULP 8-core templates and cast to `float32_t` (`21b2910`).
11. "geometrical constraints infeasible" from the tiler. Means L1 memory. `--l1 128000` on Siracusa,
    `--l1 110000` on GAP9 with the stacks-in-L2 harness.
12. GAP9 "Allocation failed for allocator 2" then a DMA crash. Tiling arena larger than usable L1
    (slave stacks in L1). Relocate stacks via `pi_cluster_task_stacks()` (exp13, `ed2aeba`).
13. A live 7-hour run died with a bare `gmake … Error 2`. Another script ran `rm -rf TEST_SIRACUSA` and
    killed every `gvsoc_launcher`. Scope cleanup to `PYTEST_XDIST_WORKER` (`93458a0`); use
    `pgrep -f "[g]vsoc_launcher"` (the bracket keeps pgrep from matching itself).
14. Sticky CMake cache: `TRAINING`, `OUTPUT_TOL`, `BN_FROZEN_STATS`, `NUM_CORES` persist per build dir.
    `rm -rf TEST_SIRACUSA/build_<worker>` when changing fixture kind or flags.
15. The exporter's reference covers only `data_size // n_accum` steps unless `--n-epochs`/`--n-batches`
    is given (exp12 compared 104 of 21,600 forwards). Always export the round with `--n-epochs 200`.
16. macOS Docker file cache serves stale `.py`/`.c`: `docker restart traindeeploy` after host edits;
    purge `__pycache__` and set `PYTHONDONTWRITEBYTECODE=1` for Onnx4Deeploy.
17. `_perturb_rqs_uniform` and `ApplyPerturbQuantUniform_*` keep the old modulo indexing; the
    `rqs_uniform` noise type is not validated for SpeechNet.
18. Weight dump words: int8 buffers pack 4 values per 32-bit word; reading word `k` as element `k`
    fakes a divergence. Use `extract_qzo_weights.py`.
19. The CleanUp `exp4` script docstring says pooled@99.99 while its results record pooled@99.9; trust
    the results file.
20. lr 1e-5 is a per-bench knob: it places the threshold at the |g| tail of fold 3; on fold 1 it
    transfers (QZO 88.89 vs float 88.61), but on fold 2 (hardest session, larger gradients) it
    over-moves and loses 4.86 pp to float ZO. Rule: place `0.5·s_w/lr` at the top ~1 % of a 100-probe |g| sample per deployment, or use an lr-insensitive
    update (ECO / master weights).

## 8. Open items and next steps

1. **ECO on device.** Plan: a new fused element-wise op (e.g. `ECOUpdateRQS`) replaces the update
   graph's `round(coeff·z/s_w)` rule with the ECO step of §1.3 — one pass over the ~14.9k conv weights,
   same 8-core fork as the existing perturb/update kernels (its cycle cost must be measured, not
   assumed). Add `m` (and `e` for exact EF) as fp32 weights-as-inputs of `network_zo_update`
   (`base_exporter._export_qzo_training`), ~60 kB L2 each; keep `m` and `α·e` in fp32 (α ≈ −3.7e4);
   clamp to [−127, 127] and compute the residual against the clamped value. Register the op's
   parser/bindings in Deeploy (Generic + PULPOpen tiling-ready, then GAP9 reuse, as for
   `RQSPerturbRademacher`). `m` restarts each round (each device round is a fresh runner invocation);
   persist it in L2 if rounds are chained on device. β = 0.9, lr 3e-6. Recommended order: exact EF
   (RTN; no 1/lr blow-up, 86.81 % on host) → memory-free RTN (drops `e`; write-sparse, 11.8 % of
   weights, 85.69 %) → SR variant (reuse xorshift32; 86.81 %, ~100 % writes). Validate single-step
   bit-exactness first with the `SpeechNet_Test` single-step fixture and the exp7/exp8 tooling. Use the
   pooled@99.9 calibration (`SpeechNet_Test/calibration/pooled_999_fold3_ref.json`, §3), the setting of the
   ECO host simulation the device run will be compared with.
2. **Device zero-shot accuracy** for the quantized model (one untiled eval on the un-fine-tuned
   `qinfer`, ~35 min). Never measured.
3. **Optional strict-fp32 debugging round on the correct weights** (exp19 used the default `-ffast-math`): confirms learning-neutrality on
   `artifacts_reference` and whether the step-1281 divergence onset reproduces.
4. **Seeds.** Every device number is one seed; 2–3 seeds before quoting any gap as an effect.
5. **Rounds 2–4 and S02–S04 on device** to match the reference table shape; host sims exist
   (CleanUp exp3, exp4, exp11–13; §6.5).
6. **Emit the reciprocal Quant scale at export** and retire the `QuantParser` inversion.
7. **Literal diff = 0 over a full lr-1e-5 round** needs a host SCE using picolibc's `sf_exp.c`/`sf_log.c`
   (`/app/toolchain/picolibc/newlib/libm/math/` in `traindeeploy`); gate prepared in
   `deliverable/exp11_bitexact_SCE/probe/`. Cosmetic; not required for the tolerance bar.
8. **Epoch budget.** Host sweeps plateau by ~50 epochs for ZO and earlier for ECO (stale weights; the
   correct-weight CleanUp exp6 sweep in §6.5 is flat between E = 100 and E = 200) — a 4× cheaper device
   round if confirmed on device.
9. Upstream report to the Deeploy maintainers: unwired parallel Quant/Dequant templates and the double
   literal promotion (affect every float-boundary PULP deployment).
10. **QZO round-1 fixture under `SpeechNet_Test`.** Not generated on purpose (§5.3); regenerate with the
    `qzo_round1` target once the ECO recipe is fixed, then run `scripts/crosscheck.py` against
    `speechnet_qzo19_{train,update}`.
