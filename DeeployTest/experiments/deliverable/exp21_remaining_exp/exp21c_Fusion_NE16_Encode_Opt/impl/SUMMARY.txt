REVIEW CORRECTIONS TO THE exp21c ANALYSIS
  1 Hoisting is exact in the shipped recipe (seed_base set once per update step, deeploymezotest.c:667, outside the
    accum loop :669; only the MeZO harness writes perturb_seed_base; W/add change only in the update graph / resume).
    WRONG before: "the single-update-step fixture catches a stale cache" -- it cannot (staleness appears from step 2);
    multi-step runs were added (below).
  2 n_accum != 4: saving = (n_accum-1)/n_accum of the prep; n_accum = 1 only pays the cache fill.
  3 q > 1: the harness evaluates one direction per step whatever ZO_Q; a per-direction seed would be a separate key.
  4 Kernel fixtures run the graph once -> H is always a miss there (+fill: 2.7 k / 3.7 k / 4.8 k / 8.6 k on B1-B4);
    H can only be measured in the network.
  5 input_offset = 0 holds for network blocks 1-4 (stacked, Relu upstream: ZODualPassFusion.py:232), NOT block 0
    (128), and NOT the exp11 fixtures (128) -> new fixtures impl/fixtures/QZO_DualConv2in_NE16P_off0_B<i>.
  6 The H estimate (whole prep gone in 3 of 4 windows) was optimistic: a hit still costs the node fork, the tiled DMA of
    W in / output out and the cache copy: 1.2-1.4 k (bias, block-0 wenc), 3.7-3.9 k (block 1/2 wenc), 5.7 k (b3), 10.5 k (b4).
  7 Same code, different cycles: the tiler (random-max) generates slightly different code per run; base 6,543,740 (exp21c)
    / 6,562,634 / 6,554,297 (this tree) -> noise ~ +-0.15 %. Speedups below are vs the mean 6,558,466.
